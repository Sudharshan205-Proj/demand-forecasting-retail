# Phase 15 — Visualization Quality Framework

## Data Integrity

Visualizations must use established project outputs.

## Calculation Integrity

Displayed values must reconcile with source analytical files.

## Scale Integrity

Axes must not use misleading truncation where it changes interpretation.

## Label Integrity

Charts must identify:

- what is measured;
- unit or interpretation;
- grouping variable;
- relevant time/scenario assumptions.

## Accessibility

The dashboard should:

- use readable text;
- avoid relying solely on colour;
- provide descriptive labels;
- maintain sufficient visual distinction;
- avoid unnecessary visual complexity.

## Audience Awareness

Technical model terminology should be explained when required.

## Visual Hierarchy

The most important findings should receive the strongest visual emphasis.

## Clutter Control

Avoid:

- unnecessary decoration;
- excessive chart count;
- redundant legends;
- overly dense labels;
- unnecessary grid elements.

## Leakage Control

No visualization should expose test-period observations in a way that
could have influenced model selection or tuning.

## Scenario Transparency

Inventory scenario charts must clearly communicate that lead times and service
levels are assumptions.

## Reproducibility

Static visualizations must be generated by source code.

Tableau source data and dashboard structure must be documented.

## Validation

Visualization values must be checked against established CSV outputs before
being treated as verified project evidence.
