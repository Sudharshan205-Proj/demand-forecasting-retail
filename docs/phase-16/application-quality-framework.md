# Phase 16 — Application Quality Framework

## Functional Quality

The application must:

- Load required analytical artifacts.
- Reject missing artifacts clearly.
- Display valid store selections.
- Display demand metrics.
- Display inventory scenarios.
- Display model evaluation results.
- Explain the evidence behind each store's selected model, including the weaker single-fold basis of Store 4's configuration.
- Explain scenario assumptions.

## Data Quality

Application inputs must:

- Exist.
- Be readable as CSV.
- Contain rows.
- Contain required identifiers.
- Preserve the analytical results generated by previous phases.

## Software Quality

The application should:

- Use project-relative paths.
- Separate responsibilities.
- Avoid unnecessary dependencies.
- Use explicit error handling.
- Avoid secrets.
- Provide maintainable code.

## Testing

The support layer must be covered by automated tests.

The full Streamlit interface must also be manually smoke-tested.

## Reproducibility

The application must be runnable using the documented environment and
commands.

## Known Limitation

Automated unit tests do not replace manual browser/UI validation.
