# Phase 14 — R Analysis Plan

## Purpose

This phase introduces an independent R/RStudio analytical, validation and
reporting workflow into the retail demand forecasting project.

R is used for:

- analytical transformation;
- descriptive analysis;
- demand variability analysis;
- inventory scenario analysis;
- cross-language verification of the Python forecasting evidence;
- visualization;
- reproducible reporting.

Python remains the primary forecasting implementation.

## Inputs

The analysis consumes the compact outputs generated by Phases 12 and 13
rather than reloading the full raw dataset:

| Input | Source | Rows |
|---|---|---|
| `inventory_demand_summary.csv` | Phase 13 | 4 |
| `inventory_variability_summary.csv` | Phase 13 | 4 |
| `inventory_scenarios.csv` | Phase 13 | 36 |
| `inventory_forecast_scenarios.csv` | Phase 13 | 36 |
| `inventory_forecast_error_summary.csv` | Phase 13 | 4 |
| `inventory_densification_summary.csv` | Phase 13 | 4 |

The first four inputs were named in the original phase plan. The five
additional artifacts were recorded by the Phase 13 re-audit as evidence
Phase 14 may consume, and the audit adopted them so that "R independently
reproduces the principal Phase 13 findings" covers the whole evidence base
rather than the historical view only.

## Analytical Tasks

### 1. Demand Analysis

Calculate and examine:

- mean daily demand;
- median daily demand;
- minimum demand;
- maximum demand;
- total training-period demand;
- densified training-day count;
- standard deviation, variance and the p90/p95/p99 percentiles;
- coefficient of variation.

### 2. Variability Analysis

Examine standard deviation, variance, percentile demand and the coefficient
of variation, and verify that both summaries publish the same CV and that it
equals σ ÷ mean.

### 3. Inventory Scenario Analysis

Examine how reorder-point scenarios change with lead time, service level,
safety stock and expected lead-time demand, in both Phase 13 families:

- historical variability;
- forecast residual error.

### 4. Phase 13 Consistency

Independently reproduce all 13 published insights across the seven insight
types, reconciling store, metric name and value, and reconcile the
densification measurement.

### 5. Phase 12 Forecast Verification

Recompute RMSE, MAE and MAPE from the 456 stored validation forecasts with
`yardstick` and reconcile them with the reported metrics, so the forecast
evidence is verified in a second language.

## Visualization

Use ggplot2 to produce:

- average demand by store;
- demand variability by store;
- reorder-point scenarios by lead time and service level;
- a faceted comparison of the historical and forecast-error families.

Faceting is used for store-specific and family-specific comparisons, and all
figures are exported with `ggsave()`.

## Reporting

R Markdown provides:

- YAML metadata;
- Markdown narrative;
- executable R code chunks that call the audited workflow;
- generated tables;
- generated visualizations;
- the quality-report summary and `sessionInfo()`;
- reproducible HTML reporting that refuses to knit if validation fails.

## Validation

`r_analysis_quality_report.csv` records 91 checks and gates the run. The
findings report is written only when every check passes. The R Markdown
report calls the same `main()` and asserts the same gate.

## Scope Boundary

This phase does not replace the Python forecasting models.

No unsupported production inventory assumptions are introduced.

R is used as an independent analytical, validation and reporting workflow;
RStudio itself is not evidenced, because the executed workflow runs through
`Rscript`.

## Reproducibility

| Item | Value |
|---|---|
| Script | `r/r_analysis.R` |
| Report | `r/r_analysis_report.Rmd` |
| Tests | `tests/test_r_analysis.py` |
| Run | `Rscript r/r_analysis.R` (from the repository root or `r/`) |
| Render | `Rscript -e "rmarkdown::render('r/r_analysis_report.Rmd', output_dir = file.path(getwd(), 'data', 'analysis', 'r'))"` |
| Test | `.venv\Scripts\python.exe -m pytest tests/test_r_analysis.py -q` |
| Path overrides | `R_ANALYSIS_PROJECT_ROOT`, `R_ANALYSIS_INPUT_DIR`, `R_ANALYSIS_OUTPUT_DIR` |

Outputs are written to `data/analysis/r/` and `data/analysis/r/plots/`, both
excluded from Git under the generated-artifact policy.
