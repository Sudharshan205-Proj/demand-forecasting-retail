# Phase 15 — Visualization Quality Framework

Each principle below is stated together with how it is enforced. A principle with
no mechanism is listed under "Not mechanically enforced" rather than claimed.

## Check inventory

`data/analysis/visualization_quality_report.csv` is the authoritative enumeration
of all **55** checks, with a `check`, `status` and `detail` column per row. The
checks are grouped by family below rather than listed one by one; measured family
sizes are `demand_*` 8, `variability_*` 8, `scenarios_*` 16, `insights_*` 10,
`validation_*` 6, `leakage_*` 3 and `figure_*` 4 — 55 in total. Read the CSV for
the exact membership.

## Data Integrity

Visualizations must use established project outputs.

*Enforced:* the workflow declares exactly five inputs, loads only those files,
and fails if any is missing.

## Calculation Integrity

Displayed values must reconcile with source analytical files.

*Enforced:* the coefficient of variation, the variance identity, percentile
ordering, the z value, expected lead-time demand, safety stock and the reorder
point are each recomputed and compared with the stored value. Every insight value
is reconciled to its source, including the 14-day / 95 % scenario reorder points.
All 55 results are written to `visualization_quality_report.csv`.

## Scale Integrity

Axes must not use misleading truncation where it changes interpretation.

*Enforced:* matplotlib auto-scales with an explicit margin, so no static figure
sets a fixed range, and the Tableau `Reorder-Point Scenarios` sheet carries a
fixed **7 → 28** range — the smallest and largest assumed lead times — so the axis
cannot imply observations between them. Both axes and both scenario sheets are
re-checked after any shelf change, so a re-introduced fixed range would be caught
before the next save.

## Label Integrity

Charts must identify what is measured, the unit or interpretation, the grouping
variable and the relevant time/scenario assumptions.

*Enforced:* every figure title names the measure; every axis states its unit and,
where relevant, that it covers the training period; the scenario chart's axis
states that lead time is a planning assumption; the RMSE chart states that the
measure is not comparable across stores.

## Accessibility

The dashboard should use readable text, avoid relying solely on colour, provide
descriptive labels, maintain visual distinction and avoid unnecessary complexity.

*Enforced:* colour-independent distinctions and tooltips are present in the
workbook, the static figures use labelled axes rather than a colour legend, and
the human usability and accessibility review of the rendered interface is
complete.

## Audience Awareness

Technical model terminology should be explained when required.

*Enforced:* the RMSE figure defines its own limitation on the axis; the scenario
figure defines lead time as an assumption.

## Visual Hierarchy

The most important findings should receive the strongest visual emphasis.

*Enforced by construction:* each figure answers one question, and the scenario
chart emphasizes the 95 % baseline used throughout the narrative.

## Clutter Control

Avoid unnecessary decoration, excessive chart count, redundant legends, overly
dense labels and unnecessary grid elements.

*Enforced:* four figures only; single-series charts carry no legend; the scenario
chart uses a light horizontal gridline and no vertical gridlines.

## Leakage Control

No visualization should expose test-period observations in a way that could have
influenced model selection or tuning.

*Enforced:* the workflow declares no test-period artifact as an input, asserts
that the demand summary carries its training window, and asserts that the
forecast-evidence insight is derived from `validation_rmse` rather than a test
metric. All three are recorded as checks, and the guard is unit-tested.

## Scenario Transparency

Inventory scenario charts must clearly communicate that lead times and service
levels are assumptions.

*Enforced:* the assumption is written into the chart's axis label and repeated in
[`data-storytelling.md`](data-storytelling.md) and the Tableau specification.

## Reproducibility

Static visualizations must be generated by source code. Tableau source data and
dashboard structure must be documented.

*Enforced:* the figures are generated by `scripts/create_visualizations.py`; the
workbook structure is documented in
`tableau/tableau-dashboard-specification.md` and
`tableau/tableau-data-dictionary.md`, and is re-verified by the test suite. The
workbook's cached schema is reconciled against the CSV headers by
`scripts/sync_tableau_workbook_schema.py`, which is idempotent.

## Validation

Visualization values must be checked against established CSV outputs before being
treated as verified project evidence.

*Enforced:* the run is gated on 55 checks, and the run exits non-zero without
drawing any figure if a single check fails. Four figure checks then confirm each
file was written non-empty, and the manifest records its digest.

## Not Mechanically Enforced

- Human usability and accessibility review — a human judgement rather than a
  machine check.
- Subjective clutter and colour judgement.
- Whether the chosen chart type is the most persuasive for a given finding.

These are recorded as PARTIAL in
[`course-content-coverage.md`](course-content-coverage.md) rather than marked
verified.
